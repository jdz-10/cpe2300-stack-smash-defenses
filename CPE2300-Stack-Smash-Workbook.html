For every core objective and add-on, define how you will prove that it works. This becomes the approved checklist for your final demo and evaluation.

Use AI carefully: you may use AI to improve the clarity and coverage of your test cases—for example, to suggest edge cases or make an input/output expectation measurable. You must review every test yourselves. Do not use AI to generate assembly code.

GitHub

First Steps

new to GitHub? start here

Your project lives in one shared repo. There are three ways to do everything — pick whichever you like, and you can mix them:

  • Web interface (github.com) — do it in your browser, nothing to install. Easiest to start.
  • GitHub Desktop (app from desktop.github.com) — buttons on your computer; best for everyday work.
  • Command line (git from git-scm.com) — type commands in a terminal; fastest once you know it.

1 · Create your first repository (one teammate does this)

  • Web: on github.com click + (top-right) → New repository, give it a name, click Create repository. Then open Settings → Collaborators and add your two teammates.
  • Desktop: File → New repository, set a name and a local folder, Create repository, then Publish repository.
  • Command line: create the empty repo on github.com, copy its URL, then git clone <url> to get a folder on your computer.

2 · Add your files to the repo

  • Web: open the repo, click Add file → Upload files, drag your .s files in, then Commit changes.
  • Desktop: copy your .s files into the repo folder on your computer — they appear in GitHub Desktop. Type a Summary, Commit to main, then Push origin.
  • Command line: copy your files into the repo folder, then: 
    git add -A                # stage the new files
git commit -m "add files" # save a snapshot
git push                  # upload to GitHub

3 · Save & share changes (do this often)

  • Web: open a file, click the pencil to edit, then Commit changes.
  • Desktop: type a short Summary, Commit to main, then Push origin.
  • Command line: git add -A → git commit -m "message" → git push.

4 · Get teammates' latest first

  • Web: the browser always shows the newest version.
  • Desktop: click Fetch origin, then Pull.
  • Command line: git pull.

Tips

  • Commit small and often with clear messages — your commit history is part of the grade.
  • Pull before you start, push when you finish — it avoids most conflicts.
  • Merge conflict? If two people changed the same lines, open the file, keep the correct lines, delete the <<<< ==== >>>> markers, then commit.
  • Put your weekly PDF report in a reports/ folder in the repo, or submit it on Canvas.
